# Умай Групп · Ежедневная отгрузка

Веб-инструмент для складов (Пригородное / Ак-Орго / ПТО) и ОТЛ: склад вносит заказы,
ОТЛ видит консолидацию и транспорт, выгрузка идёт готовым .xlsx в формате ТМС.

Технологии: React + Vite, Firebase Firestore (общее хранилище данных), хостинг — GitHub Pages.

**Версия без авторизации.** Ссылка на сайт открытая: у кого она есть — тот видит и может
менять все вкладки, без входа и без разделения по ролям. Конфиг Firebase-проекта
`umai-tms` уже вписан в код (`src/firebase.js`) — ничего дополнительно вводить не нужно.

---

## Что нужно перед началом

- аккаунт на [github.com](https://github.com)
- у вас уже есть проект `umai-tms` в [console.firebase.google.com](https://console.firebase.google.com) — используем его

---

## Шаг 1. Включить Firestore (если ещё не включена)

1. [console.firebase.google.com](https://console.firebase.google.com) → проект **umai-tms**
2. **Build → Firestore Database → Create database**
3. Режим: **Production mode** → регион любой → **Enable**

### Вставить правила доступа

1. Вкладка **Rules** → удалите всё, что там есть → вставьте:

```
rules_version = '2';

service cloud.firestore {
  match /databases/{database}/documents {
    match /shipments/{date} {
      allow read, write: if true;
    }
  }
}
```

2. **Publish**

(Тот же текст лежит в файле `firestore.rules` в этом архиве.)

Если Firestore и правила у вас уже настроены с прошлого раза — этот шаг можно пропустить.

---

## Шаг 2. Выложить код на GitHub

1. На github.com → **New repository** → имя **обязательно** `umai-shipment`
   (если хотите другое имя — поправьте строку `base` в `vite.config.js`)
2. Загрузите туда все файлы из этого архива — можно через `git`:

```bash
cd umai-shipment
git init
git add .
git commit -m "Initial commit"
git branch -M main
git remote add origin https://github.com/ВАШ_АККАУНТ/umai-shipment.git
git push -u origin main
```

или просто через веб-интерфейс GitHub: **Add file → Upload files**, перетащить всю
папку — тоже сработает.

---

## Шаг 3. Включить публикацию (GitHub Pages)

1. В репозитории: **Settings → Pages**
2. **Source** → **GitHub Actions**

---

## Шаг 4. Запустить сборку

Обычно сборка запускается сама после первого `push`. Если нет:

1. Вкладка **Actions** в репозитории
2. Слева **Deploy to GitHub Pages** → справа **Run workflow** → **Run workflow**
3. Через 1–2 минуты — зелёная галочка

## Про безопасность конфига

`apiKey` в `src/firebase.js` — это не пароль, у Firebase он всегда виден в коде
веб-приложения, так и задумано. Реальная защита данных — правила Firestore (шаг 1):
сейчас они открытые (`allow read, write: if true`), то есть данные может писать кто
угодно, кто знает `projectId`, а не только те, у кого есть ссылка на сайт. Для
внутреннего рабочего инструмента на доверии это нормально; если понадобится
ограничить — можно вернуться к версии с логином и ролями (обсуждали раньше, могу
поднять снова).

## Ограничения этой версии

- Нет входа и ролей — любой человек со ссылкой видит и может редактировать любую вкладку
- Нет журнала изменений — при одновременном редактировании одной вкладки побеждает тот, кто сохранил последним
- Экспорт в Excel — под формат файла «Шаблон импорта в ТМС»; если формат в ТМС поменяется, править `src/lib/exportExcel.js`
- Список машин и магазинов зашит в `src/data/reference.js` на сегодняшний день — новые добавлять туда вручную
